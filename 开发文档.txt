UDS诊断自动化测试框架开发文档
1. 概述
本文档详细介绍了UDS诊断自动化测试框架中的核心函数、数据结构和使用方法，主要用于汽车电子控制单元(ECU)的诊断测试自动化。

3.3 响应比较函数
compareResponse
c
/**
 * 通用诊断响应比较函数
 * @param diag_return 诊断响应结构体
 * @param expLen 期望长度（NOT_USED=999表示忽略此参数）
 * @param check_string 检查字符串
 * @param mode 比较模式（0=完全，1=事件码，2=部分）
 * @param exstatus 期望状态（positive=-1积极响应，0=无响应，>0=否定响应）
 * 
 * 比较模式说明：
 * - 0=完全匹配：比较长度和全部字节
 * - 1=响应值对比：只比较响应状态，不比较长度
 * - 2=部分对比：比较前几个字节和整个响应长度
 */

mode=1（COMPARE_EVENT_CODE）：最后一个参数是期望状态（-1=positive、0=no response、>0=negative）。

mode=2（COMPARE_FIRST_BYTES）：最后一个参数是**“前缀对比的字节数”，而 expLen 表示期望的整条响应长度**




compareResponse(diagResp, 3, "0x7F2213", 0, NOT_USED);
cmpbyte
c
/**
 * CAN FD报文监控比较函数
 * @param ID 监控的消息ID
 * @param dest_string 目标字符串（转换为字节数组比较）
 * @param maxwaittime 最大等待时间（毫秒）
 * @param cmpLength 比较长度（字节数）
 * @param mode 比较模式
 * 
 * 注意事项：
 * - 必须在发送前监控，不能有WAITFIR时间间隔
 * - 每次监控前必须重新注册事件
 * - 发送和监控不能阻塞，否则会丢失响应
 * 
 * 使用示例：
 * cmpbyte(0x7CF, "10", 150, 1, COMPARE_FIRST_BYTES); // 监控首帧
 */
cmpbyte(0x7CF, Resp_string_1000, 150, 1, COMPARE_FIRST_BYTES);

5. 重要注意事项
数组大小限制：

避免使用190A服务，可能超出DTC_list[2000]限制

desDTC[8192]缓冲区足够处理大多数响应

时序控制：

必须使用testWaitForTimeout确保响应完成

发送和监控操作不能阻塞

事件注册：

每次监控前必须重新调用TestJoinMessageEvent

CAN FD通信必须设置正确的总线上下文

稳定性保障：

对于多次DTC检查，推荐复制响应数据到独立数组

使用专门的DTC检查函数而非手动解析

错误处理：

安全解锁失败会自动报告

网络休眠检查失败会标记测试失败

日志管理：

合理使用日志标志控制输出详细程度

确保每个测试用例有完整的开始和结束日志
